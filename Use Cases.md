| UC-01 | Совместное планирование маршрута группой с проверкой конфликтов |
|---|---|
| **Акторы** | Организатор поездки, Участники группы, Внешние поставщики (отели, активности, трансферы) |
| **Предусловия** | Организатор авторизован; создана поездка с направлением, датами, бюджетом; приглашены минимум 2 участника; участники приняли приглашение |
| **Триггер** | Организатор открывает маршрут и нажимает «Добавить элемент» |
| **Основной сценарий** | 1. Система показывает форму добавления элемента<br>2. Организатор выбирает тип: рейс, отель, трансфер, активность<br>3. Организатор указывает время, место, длительность<br>4. Система проверяет элемент на конфликты (пересечения, стыковки, тайм-зоны, заселение)<br>5. Конфликтов нет<br>6. Система добавляет элемент со статусом «предложен»<br>7. Система уведомляет всех участников<br>8. Участники видят элемент в реальном времени<br>9. Участники голосуют «за»/«против» с комментариями<br>10. Система собирает голоса и показывает результат<br>11. Большинство голосует «за»<br>12. Организатор подтверждает элемент<br>13. Система переводит элемент в «подтверждён»<br>14. Система обновляет таймлайн<br>15. Система уведомляет всех участников<br>16. Участники видят финальный маршрут |
| **Альтернативные сценарии** | 4a. Найден конфликт:<br>• 4a1. Система показывает описание конфликта и его критичность.<br>• 4a2. Система предлагает варианты решения (сдвинуть время, выбрать другой элемент).<br>• 4a3. Организатор либо корректирует, либо сохраняет с предупреждением.<br>• 4a4. Если сохраняет - элемент помечается как «конфликтный».<br><br>6a. Элемент не найден у поставщика:<br>• 6a1. Система сообщает, что элемент недоступен.<br>• 6a2. Система предлагает похожие варианты.<br><br>9a. Участник не согласен:<br>• 9a1. Участник голосует «против» и оставляет комментарий.<br>• 9a2. Организатор получает уведомление.<br>• 9a3. Организатор либо меняет элемент, либо оставляет с обоснованием.<br><br>9b. Участник не голосует:<br>• 9b1. Через 48 часов система напоминает участнику.<br>• 9b2. Если участник не голосует - голос не учитывается.<br><br>11a. Голоса разделились:<br>• 11a1. Система показывает равный результат.<br>• 11a2. Организатор принимает финальное решение.<br><br>12a. Организатор отклоняет элемент:<br>• 12a1. Элемент переходит в статус «отменён».<br>• 12a2. Участники уведомлены.<br><br>15a. Участник офлайн:<br>• 15a1. Система сохраняет уведомление.<br>• 15a2. Участник получит его при следующем входе. |
| **Постусловия** | Элемент добавлен и подтверждён, все участники уведомлены, таймлайн обновлён, конфликтов нет |

|**UC-02** | **Получение персонализированных рекомендаций и обратная связь** |
|---|---|
| **Акторы** | Путешественник, Внешние поставщики (отели, активности) |
| **Предусловия** | Пользователь авторизован; заполнены предпочтения; согласие на персонализацию; есть история поездок/отзывов; создана поездка с направлением и датами |
| **Триггер** | Пользователь открывает раздел «Рекомендации» в поездке |
| **Основной сценарий** | 1. Система собирает данные о пользователе (интересы, история, оценки, поведение)<br>2. Система формирует пул кандидатов по направлению (отели, активности, рейсы)<br>3. Система ранжирует кандидатов на основе предпочтений, истории, бюджета, доступности<br>4. Система показывает рекомендации<br>5. Пользователь просматривает и кликает на интересную рекомендацию<br>6. Система фиксирует клик и обновляет предпочтения<br>7. Пользователь добавляет рекомендацию в маршрут<br>8. Система фиксирует конверсию и обновляет модель на основе обратной связи |
| **Альтернативные сценарии** | 1a. Недостаточно данных:<br>• 1a1. Система определяет, что данных мало.<br>• 1a2. Система показывает популярные варианты по направлению.<br>• 1a3. Система предлагает пройти короткий опрос интересов.<br>• 1a4. После опроса - сценарий продолжается с шага 2.<br><br>2a. Мало кандидатов по направлению:<br>• 2a1. Система расширяет радиус поиска.<br>• 2a2. Система повторно ранжирует.<br><br>5a. Пользователь отклоняет рекомендацию:<br>• 5a1. Пользователь нажимает «Не интересно».<br>• 5a2. Система фиксирует негативный сигнал, обновляет предпочтения и предлагает другие варианты. |
| **Постусловия** | Рекомендации показаны, обратная связь зафиксирована, предпочтения обновлены |

| UC-03 | Обработка изменения рейса и перебронирование |
|---|---|
| **Акторы** | Организатор поездки, участники группы, Авиаперевозчик, Платёжный провайдер |
| **Предусловия** | Есть подтверждённая бронь рейса; в маршруте есть связанные элементы (отель, трансфер, активности) |
| **Триггер** | Авиаперевозчик сообщает об изменении рейса (задержка, отмена, изменение времени) |
| **Основной сценарий** | 1. Система получает уведомление от перевозчика<br>2. Система проверяет, не обрабатывалось ли это уведомление ранее<br>3. Система находит затронутые бронирования, поездки и маршруты<br>4. Система анализирует влияние (стыковки, заселение, трансфер, активности)<br>5. Конфликтов нет - изменение некритичное<br>6. Система помечает событие как обработанное<br>7. Система уведомляет всех участников<br>8. Участники видят изменение и обновлённый маршрут |
| **Альтернативные сценарии** | 5a. Найден критичный конфликт (невозможна стыковка):<br>• 5a1. Система помечает изменение как критичное.<br>• 5a2. Система подбирает альтернативные рейсы у перевозчика и формирует варианты для организатора.<br>• 5a3. Система уведомляет организатора с вариантами.<br>• 5a4. Организатор выбирает вариант.<br>• 5a5. Система создаёт новое бронирование и рассчитывает разницу в цене (доплата или возврат).<br>• 5a6. Система подтверждает новую бронь и отменяет старую у перевозчика.<br>• 5a7. Система обновляет маршрут.<br>• 5a8. Система уведомляет всех участников.<br><br>5b. Конфликт с отелем:<br>• 5b1. Система показывает, что заселение невозможно.<br>• 5b2. Система предлагает варианты: сдвинуть заселение, выбрать другой отель.<br>• 5b3. Организатор принимает решение.<br><br>5c. Бронь невозвратная:<br>• 5c1. Система показывает сумму штрафа.<br>• 5c2. Организатор решает: принять штраф или оставить старый вариант.<br>• 5c3. Если принимает - продолжается перебронирование.<br>• 5c4. Если отказывается - система оставляет старую бронь с предупреждением. |
| **Постусловия** | Все участники уведомлены, маршрут синхронизирован, при необходимости - перебронирование |
